## 5. 需用户确认的事项（4 项）

> 每项给出选项与影响，**不做假设**。

### 决策 1：本轮范围（必选）

| 选项 | 内容 | 工作量 | 影响 |
|---|---|---|---|
| **A（推荐）** | 模块 A+B+C+D+E（鉴权 + 前端闭环 + 预警骨架 + 调度加固 + 文档） | 大（本轮交付完整可用系统） | 一次到位，可演示"登录→看板→预警→监控" |
| B | 仅 A+B（鉴权 + 前端闭环） | 中 | 快速见效，但预警（产品定位核心）仍缺 |
| C | 仅 A + D（先保后端安全与调度稳定） | 小 | 最稳，但前端仍无业务页，无法演示 |

### 决策 2：Redis 定位

| 选项 | 影响 |
|---|---|
| **A（推荐）** | 本轮**不用 Redis**（无状态 JWT；缓存用 Spring 默认内存缓存）。装 Redis 后再按 profile 切换，蓝图技术栈不变 |
| B | 先安装 Redis（Windows 版）再开发 → 增加环境依赖与排障成本 |

### 决策 3：预警阈值语义（影响 DDL 字段与前端交互）

| 选项 | 含义 | 影响 |
|---|---|---|
| **A（推荐）** | **日环比涨跌幅**阈值（如 \|日环比\| ≥ 5% 触发），按品类配置 | 与现有 `change` 接口一致，实现最直接 |
| B | **周环比**（近7日均价 vs 前7日均价） | 更平滑，但需新增聚合口径 |
| C | **绝对价格上下限**（如大白菜 ≥ 1.0 元/斤 触发） | 直观，但与"波动预警"定位弱相关 |
| D | A+B+C 全支持（阈值类型字段区分） | 最灵活，工作量最大（本轮可能做不完） |

### 决策 4：调度常驻落地方式

| 选项 | 优点 | 缺点 |
|---|---|---|
| **A（推荐）** | 提供 `start-scheduler.bat` + **Windows 任务计划**注册脚本（开机自启、崩溃可配重试） | 无常驻守护进程，需系统计划任务 |
| B | 注册为 Windows 服务（NSSM/WinSW） | 最稳，但需额外下载工具、需管理员权限 |
| C | 仅手动启动（文档说明） | 最简单，但违背"数据自动更新"目标 |
